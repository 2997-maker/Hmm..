# cottontrip: 다른 AI에게 전달하는 기획과 코드 안내

## 1. 서비스 목적
해외여행자가 짐을 입력하면 여행 경로에 맞춰 무엇을 빼거나 주의해야 하는지, 기내와 위탁 중 어디에 넣어야 하는지 쉽게 확인하도록 돕는 웹사이트다. 여러 항공사와 국가의 규정을 반복해서 찾는 부담, 공항에서 짐을 버리거나 재정리하는 상황을 줄이는 것이 목표다. 효과가 검증된 서비스는 아니다.

실제 해외봉사 경험에서 운영진이 단체 짐의 무게와 금지 물품을 확인하는 데 많은 시간을 썼고, 참가자끼리 보조배터리용 절연테이프를 나눴으며, 공항에서 위탁 짐의 휴대용 고데기를 뺀 사례가 있었다. 특정 경험을 전체 여행자의 특성으로 일반화하지 않는다. 첫 대상은 개인 여행자이며 운영진 활용은 향후 가능성이다.

## 2. 현재 만들고 있는 것
- 이름: cottontrip. 한국어 웹사이트, 회원가입 없는 가벼운 시제품.
- 경로: 인천 ICN ↔ 나리타 NRT 직항 왕복. 제주항공·파라타항공 한정 조건은 삭제했다.
- 항공편 조회: 노선과 날짜에 맞는 API 응답 항공편을 항공사 제한 없이 표시. 세계 모든 노선을 지원하는 것은 아니다.
- 페이지: `/` 여행 설정 → `/packing` 짐 담기 → `/bags` 가방 무게 → `/review` 결과.
- 디자인: 솜사탕 느낌의 연분홍·라벤더·하늘색 그라데이션, 둥근 카드와 버튼, 읽기 쉬운 안내. 한 페이지에 모든 기능을 몰지 않는다.
- Figma: https://www.figma.com/design/3NnRk67sEVCoE4v6iJAW8V?node-id=14-17

## 3. 실제 구현된 기능
- 가는 편 인천 출발일과 오는 편 인천 도착일 입력, 정기 운항편 조회, 항공편 선택 또는 항공사 직접 입력. 조회 중·실패·결과 없음 안내.
- 물품 자동완성: ‘헤’ 등으로 후보 선택. 쉼표·줄바꿈 직접 입력과 자주 챙기는 물품 버튼도 제공.
- 수량 수정, 기내/위탁 배정, 목록 필터, 삭제·최근 삭제 되돌리기, 종류·무게 상세 펼침과 객관식 선택.
- 분류 불명 물품은 비교 물건과 절반/비슷함/두 배 비율 또는 모르겠음 선택.
- 목록에 없는 속옷·양말·칫솔·충전기 등 기본 준비물 제안.
- 빈 캐리어 1개의 무게 직접 입력 또는 크기·소재 시험 대표값 사용.
- 구매 페이지 주소 입력 UI는 있으나 해석은 미연결이며 대체 방법 안내.
- 기내/위탁 예상 합계와 미확인 물품 별도 표시. 빈 결과는 짐 추가로 안내.
- 물품 추가·수정·삭제 상태 알림, 단계 내비게이션, 모바일 단일 열 배치.
- 내부 이동과 브라우저 뒤로 가기에서 React 상태 유지. 새로고침/새 문서 탐색 시 초기화. 서버 장기 저장·공유·로그인 없음.

## 4. 반드시 유지할 경계
- 예상 무게는 참고용이다. 허용량 충족이나 반입 가능 판정에 사용하지 않는다.
- 무게는 조사·검증 전 시험값이며, 모르는 무게는 합계 밖에 ‘+ 물품명, 무게 미확인’으로 표시한다.
- 실제 공식 규정 판정은 미연결이다. 현재 결과의 확인일 없음·최신 여부 미확인 안내를 허위로 바꾸지 않는다.
- 항공편 조회와 수하물 규정 확인은 다른 기능이다.
- 국내 출발 항공보안, 항공사 운송 규정, 도착국 세관·검역은 구분해야 한다. 한국 출발 규정을 해외 출발 한국행에 그대로 적용하지 않는다.
- 자유 입력은 내장 목록/문자열 처리이며 LLM 연결이 아니다. 짐 목록은 외부 AI로 보내지 않는다.

## 5. 방향은 논의했으나 아직 미구현
- 초기 공식 문서는 운영자가 직접 추가. AI로 구조화·검토하는 방향.
- 공식 자료 주 1회 확인, 확인일과 최신 여부 표시.
- 실제 조사에 근거한 물품 대표 무게.
- 항공사/국가별 규정 대조 엔진, 공식 자료 자동 수집, 상품 페이지 무게 해석.
- 항공사 문의 대행, ATPCO 도입, 지원 노선 확대, 다국어는 미정 또는 장기 아이디어.
- 무료에 가까운 비용을 선호하며 Cloudflare를 후보로 검토했다. 무료 보장이나 cottontrip 배포 확정으로 해석하지 않는다.
- AI의 다중 검토만으로 규정 정확도를 보장할 수 없다. 공식 근거와 적용 조건을 함께 검토해야 한다.

## 6. 코드 지도
프로젝트 루트는 `cottontrip/`이다.

| 파일 | 역할 |
| --- | --- |
| app/layout.tsx | 공통 PackingApp 마운트와 페이지 간 상태 유지 |
| app/packing-app.tsx | 경로별 UI, 여행/물품/가방 상태, 결과 계산 |
| app/page.tsx, app/packing/page.tsx, app/bags/page.tsx, app/review/page.tsx | 라우트 진입점. 실제 UI는 PackingApp에 있음 |
| app/item-search.tsx | 자동완성 |
| lib/packing.ts | 내장 물품, 입력 처리, 시험 무게 |
| app/trip.css | 디자인·반응형·상태 표현 |
| components/ui/ | Base UI/shadcn 계열 컴포넌트 |
| app/api/flights/route.ts | 인증키를 서버에서 사용해 항공편 조회 |
| scripts/dev-local.mjs | .env.local을 읽고 개발 서버 시작 |
| scripts/run-framework.mjs | vinext 실행/빌드 |
| scripts/check-packing.mjs | 기존 기능 검사 |

기술: TypeScript, React, App Router 형태, vinext/Vite 기반 Sites starter, Tailwind/CSS, lucide-react. 일반 Next.js 실행 구조로 임의 교체하지 말 것. `build/`는 생성물이 아니라 Vite 플러그인 소스여서 포함했다. `.openai/hosting.json`도 코드가 참조하는 설정이다.

## 7. Codespaces에서 시작하기
Node.js 22.13 이상이 필요하다. 저장소 루트에서:

```sh
cd cottontrip
npm run install:ci
node scripts/dev-local.mjs
```

표시되는 포트를 Codespaces의 Ports 화면에서 열면 된다. 현재 개발 스크립트는 5173을 사용한다. localhost 주소 자체는 다른 컴퓨터에서 그대로 접속할 수 없다. Codespaces에서 실제 실행은 별도 확인이 필요하다.

항공편 키가 없다면 다른 UI 기능을 먼저 확인할 수 있다. 실제 키는 Codespaces의 비밀 환경변수로 `AIRPORT_API_KEY`를 설정하거나, 로컬 전용 `.env.local`에 넣는다. `.env.example`에는 빈 변수 이름만 있다. 인증키는 Git이나 채팅에 넣지 않는다.

```sh
node node_modules/typescript/bin/tsc --noEmit
node scripts/run-framework.mjs build
node --experimental-strip-types scripts/check-packing.mjs
```

## 8. API 연결 상세
- 로컬: `/api/flights?direction=departures&date=YYYY-MM-DD`, arrivals도 지원.
- 외부: `https://apis.data.go.kr/B551177/statusOfSPaxFlt4TripPlatform/`
- 작업: `getSPaxFlt4TripPlatformDepartures`, `getSPaxFlt4TripPlatformArrivals`.
- NRT, 페이지당 100건, 최대 20페이지, 요청당 10초 제한. 운항 기간과 요일로 필터링하고 편명+시각 중복 제거.
- 실제 운항 확인이 아닌 정기 일정. 실패 시 항공사 직접 입력으로 진행.
- 원본 환경에는 사용자가 키를 설정했지만 이번 전달본에 키는 포함되지 않는다.

## 9. 검증 기록과 저장소 주의사항
- 2026-09-17 원본에서 타입 검사·production build 통과 및 네 페이지 흐름, 자동완성, 수량 변경, 가방 합계, 삭제 복구, 입력 유지, 모바일 화면을 확인했다. 규정 정확도·무게 정확도·Codespaces 실행 검증은 아니다.
- 원본 README에는 과거 파라타 코드 및 항공사 제한 설명이 남아 있어 전달본에서는 정리했다. 최신 범위와 실제 코드를 우선한다.
- 기존 저장소 루트의 정적 사이트와 배포 워크플로는 유지했다. main push는 기존 사이트 자동 배포와 연결돼 있다.
- 이번 인수인계는 별도 브랜치/PR이며 병합·운영 배포를 실행하지 않는다.

## 10. 다음 AI에게 붙여넣을 요청
> PROJECT_CONTEXT.md와 docs/COTTONTRIP_HANDOFF.md를 먼저 읽고 cottontrip/ 코드를 확인해줘. 구현 완료와 미연결 기능을 구분하고 현재 네 페이지 UI와 시험용 안내를 유지해줘. 인증키 없이 실행 가능한 부분부터 확인하고, 이후 내가 요청하는 개선을 진행해줘. 새 배포·유료 AI·운영 정책을 임의로 결정하지 말아줘.
