# cottontrip · 여행 짐 확인 시제품

Figma: https://www.figma.com/design/3NnRk67sEVCoE4v6iJAW8V?node-id=3-2

## 실행

Node.js 22.13 이상이 필요합니다. 현재 환경에서는 패키지 설치가 완료돼 있습니다.

```powershell
node scripts/dev-local.mjs
```

표시되는 localhost 주소에서 이용합니다. 인터넷 배포는 하지 않았습니다.

## 항공편 인증키 연결

프로젝트 폴더에 `.env.local` 파일을 만들고 아래 값을 직접 입력합니다. 파일은 Git에서 제외됩니다. 키를 채팅·화면 캡처·공개 저장소에 공유하지 마세요.

```text
AIRPORT_API_KEY=발급받은_디코딩_인증키
```

서버를 재시작합니다. 인증키는 서버의 항공편 조회에만 쓰이며 화면이나 브라우저 요청에 넣지 않습니다. 가는 편은 인천 출발일, 오는 편은 인천 도착일 기준입니다.

`getSPaxFlt4TripPlatformDepartures`와 `getSPaxFlt4TripPlatformArrivals`에 NRT를 전달하고 운항 기간·요일로 결과를 추립니다. 항공사 제한은 없으며, 새 환경에서는 인증키를 별도 설정하고 연결을 확인해야 합니다.

## 현재 작동하는 부분

- 회원가입 없이 왕복 여행 선택, 실제 API 조회 시도 및 직접 선택 대체
- 쉼표·줄바꿈 기반 짐 입력, 수량 수정·삭제, 종류 객관식 선택
- 기내·위탁별 예상 무게, 빈 캐리어 포함, 비교 물건과 비율 추정
- 무게 미확인 물품 별도 표시, 기본 준비물 추가
- 물품별 시험용 주의 안내와 공식 기준 미확인 표시

## 시제품의 범위

유료 AI를 연결하지 않았습니다. 자유로운 문장 이해 대신 입력한 물품명과 내장 목록을 대조합니다. 무게는 조사·검증 전 시험값이며 실제 규정 판정은 제공하지 않습니다. 여행 선택에 따라 검증된 규정이 달라지는 완성 서비스가 아닙니다.

캐리어 구매 페이지 읽기는 연결되지 않았으며, 실패 안내 후 직접 입력·크기 소재 추정으로 진행합니다. 공식 문서 등록·AI 다단계 검증·주간 갱신 작업은 아직 연결되지 않았습니다. 안내에 기준 확인일 없음과 최신 여부 미확인을 표시합니다. 캐리어는 시제품에서 1개를 다룹니다.

입력 정보는 React 메모리에서만 유지되며 새로고침하면 사라집니다. 서버 장기 저장·로그인·공유 기능은 없습니다. 이 시제품의 짐 목록은 외부 AI로 전송되지 않습니다.

## 검증

```powershell
node node_modules/typescript/bin/tsc --noEmit
node scripts/run-framework.mjs build
node --experimental-strip-types scripts/check-packing.mjs
```

Sites portable starter를 사용했습니다. Windows에서 플러그인 실행 도구의 npm 경로 해석이 실패해 동일 프로젝트의 설치·빌드 스크립트를 직접 실행했습니다. Cloudflare 배포 여부는 이후 결정합니다.

## 현재 항공사 범위
제주항공·파라타항공 한정 조건을 제거했습니다. 인천↔나리타 노선과 날짜에 맞는 API 응답 항공편을 항공사 제한 없이 표시하며, 항공사는 직접 입력할 수도 있습니다. 항공편 조회는 수하물 규정 검증을 뜻하지 않습니다. 기존 항공사별 규정 초안은 현재 MVP에서 제외했습니다. ATPCO 도입과 지원 규정 범위는 미정입니다.

## UI/UX: 네 페이지 흐름 (2026-09-17)

- `/`: 여행 설정과 실제 항공편 조회, 직접 항공사 입력.
- `/packing`: 자동완성, 직접 입력, 물품 수량·기내/위탁 변경, 상세 펼침, 삭제 및 최근 삭제 되돌리기, 준비물 제안.
- `/bags`: 빈 가방 무게 입력과 기존 추정 방식.
- `/review`: 물품별 시험용 안내와 기내/위탁 예상 합계; 목록이 비었으면 짐 추가로 안내.
- 루트 레이아웃에서 입력 상태를 유지하므로 내부 페이지 이동 및 브라우저 뒤로 가기에도 입력을 유지한다. 새로고침/직접 URL 탐색 시 초기화한다.
- 단계 내비게이션, 변경 알림, 키보드 포커스, 44px 이상 주요 조작 영역, 작은 화면의 단일 열 배치를 적용했다.
- Figma: https://www.figma.com/design/3NnRk67sEVCoE4v6iJAW8V?node-id=14-17 (네 단계 구성 및 내비게이션 프로토타입; 실제 계산·입력은 웹사이트에서 동작).

### 확인한 범위

- TypeScript 검사 및 vinext production build 통과.
- 브라우저: 자동완성 선택 → 물품 추가 → 수량 변경 → 가방 무게 입력 → 결과 합계 확인.
- 내부 이동 및 브라우저 뒤로 가기에서 여행 정보·물품·가방 입력 유지 확인.
- 물품 삭제·되돌리기, 상세 펼침, 결과 페이지 직접 진입 시 빈 상태 확인.
- 375px 뷰포트(스크롤바 제외 콘텐츠 폭 360px)에서 네 페이지 시각 확인; 가방·결과 페이지 가로 넘침 없음.
- Figma 네 화면 렌더링과 각 단계의 이동 목적지 확인.

규정 검증, 구매 페이지 해석, 예상 무게의 정확도는 이번 UI 작업으로 검증되거나 새로 연결된 기능이 아니다. 기존 시험용 안내를 유지한다.
